# 自动版本检测与 AI Agent 更新

打开插件时自动检查官方 GitHub 最新正式发布，访问 /releases/latest 网页并核验 HTTP 状态与最终版本地址，无需点检查按钮。默认首页仍是两个输入框；发现新版时底部显示“更多 · 有新版本”。展开“更多”可查看当前版本、检测结果和检查时间。

结果分为：发现新版、与 GitHub 最新正式版相同、本地版本更高（不降级）、无法确认。检查针对 GitHub 标记的 latest 正式发布，不按字符串大小排序，也不把草稿或预发布当作正式更新。超时、离线、403/429、404、没有有效版本地址都不会显示“已是最新版”。每次打开会触发检查；成功结果缓存2分钟、失败30秒，缓存会明确显示检查时间。并发请求合并，减少频繁打开时的重复网络请求。

## 更新只需复制一次指令

1. 展开“更多 → 软件更新”。
2. 点击“复制 AI 更新指令”。
3. 粘贴给能操作这台电脑的 AI Agent，让它实际执行。

指令包含当前插件版本、检查到的版本、检查时间、扩展 ID，以及固定官方仓库。它要求 Agent 自动定位本机目录、重新确认最新版、下载完整发行包、校验 SHA-256、备份旧版、更新 UI/功能/CLI、重新加载、只读验证和在失败时安全回退。普通复制粘贴插件用户无需为了检查或复制指令安装 CLI。

这是本机升级任务，不是业务计划问卷。Agent 不应反复询问是否继续，也不能操作真实鼠标、修改网站计划、替普通用户发布上游版本。用户登录、浏览器强制授权或安全权限显著扩张等真实阻塞须如实报告。没有本机工具的普通聊天 AI 不能直接安装软件。

**复制指令并不等于完成升级。** 插件不自动下载执行远端代码或替换自身；必须由 Agent 实际执行并提供版本回读。指令遵循用户当前授权和 Agent 本身的权限，不能越过浏览器许可。未进行所有新设备上的 Agent 升级/回滚端到端验收。

## 换电脑

复制文本中的扩展 ID 和版本只是线索；Agent 必须重新发现新电脑的真实目录、ID、Node 与浏览器状态。不要迁移旧机器的认证配置，不照搬作者路径。新设备部署按 [跨电脑手册](CROSS_DEVICE.md)，普通用户安装按 [Windows 手册](WINDOWS_INSTALL.md)。

## 数据与来源

检测只对固定地址 https://github.com/mkiekuum/xutu-control-terminal/releases/latest 发 HEAD 请求，跟随 GitHub 的跳转。只有 HTTP 200，且最终地址严格为本仓库 /releases/tag/v版本号，才比较版本。不会依次猜测不存在的下一个版本号；404 页面即使有 HTML 也表示不存在。无跳转的 200 错误页或其他仓库链接同样不能通过。

服务器不支持 HEAD（405/501）时才对同一个地址使用 GET；读取状态与地址后取消响应正文。请求总超时为 10 秒。不调用 GitHub 版本 API，不读取自定义版本文件，不解析或执行网页正文。不携带登录凭据、计划、人员或网站 Cookie。只增加 GitHub 官网主机权限；扩展消息入口仅接受自身 UI，调用者不能指定任意 URL。

缓存只接受此网页检测的新格式，旧 API/文件检测缓存不会继续使用。检查失败显示“无法确认”，不影响计划终端。网络或代理仍可能阻止 GitHub 访问，此时不能宣称最新版。

远端发布正文不会进入复制指令；只复制校验过的版本、检查时间和固定官方地址。下载软件和 SHA256SUMS 是后续 AI Agent 升级步骤，不属于自动检测；SHA256SUMS 校验完整性，不是独立签名。
