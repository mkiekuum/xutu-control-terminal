发布继续使用既有 release.yml，正式 tag、两个 ZIP、SHA256SUMS；源代码打包只纳入 mcp 中显式白名单文件。维护者检查复制密钥边界、预览绑定、队列防重、侧栏可逆与核心恢复回归。不因自动更新清空历史或重放未知写入。

# 换电脑、分享与升级

普通使用者下载官方最新 chrome.zip，解压、按 [Windows 安装](WINDOWS_INSTALL.md) 加载并登录自己的网站账号。不需要命令行宿主、Node.js、GitHub 登录或旧电脑路径。不要分发含真实计划的浏览器配置、DOM、离线快照、Cookie 或本机日志。

十批历史和防重复记录属于原浏览器配置，不自动跨电脑同步。新设备重新读取网站当前计划；旧 requestId 的去重不能跨安装保证，尤其不要在新电脑重放结果未知的旧写入。先核对服务器状态，再形成明确的新修改。

## 可交给有本机工具的 AI

在现有授权内独立定位安装目录和版本、下载官方包与 SHA256SUMS、核对哈希、备份旧代码、更新完整 UI/功能/提示词、运行测试及只读兼容检查。保护用户未提交修改与浏览器存储；不以维护为由写生产计划，不发业务问卷。仅登录、必须本人完成的浏览器授权和超出授权的高风险操作留下明确阻塞；无须负责人在线选择普通方案。

路径来自实际加载目录和本机工作区，不套用作者机器路径。维护源码时才需要 Node 和 pnpm；普通安装不需要。没有安装管理权限时完成 ZIP 和源码准备，准确区分“文件已更新”与“浏览器已重载”。不控制真实鼠标，不绕过浏览器许可。

更新使用完整同版 chrome/source 包，不只更新文档。原路径覆盖有利于保留开发者扩展身份。先确认无在途写入，必要时可回退代码；新增 IndexedDB 与旧 snapshot/job 存储互不覆盖，但回退旧版本不应重放新版本未知请求。

v2.5 删除 CLI 和 Native Messaging；不用迁移 .xutu 下的宿主配置或注册它。旧系统安装文件不在新包中，只在核实归属和无在途工作后清理。无需访问他人的用户名、计划或密钥。

验收：实际加载版本正确，需求/JSON/帮助/恢复入口可见，兼容性报告只读可复制，账号与目标正确。未实际完成的新设备安装必须标未验证。
