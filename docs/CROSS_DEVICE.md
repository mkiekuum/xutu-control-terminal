# 换电脑、分享、安装与升级手册

适用于Windows普通使用者以及已获授权的本机维护AI。可自动执行的检查、下载、校验、安装、配置和验证应自主完成，不发问卷。只有登录、浏览器强制的用户确认或超出已有授权的安全操作才需要人工介入。没有本机工具的聊天AI只能提供步骤，不能声称已安装。

## 选择用法

- 只需要把需求发给AI、粘贴JSON执行：安装Chrome扩展即可，不需要Node、GitHub登录或CLI。
- 需要本机AI直接调用：安装Windows整合包和Native Messaging宿主。

下载地址：https://github.com/mkiekuum/xutu-control-terminal/releases/latest 。普通使用者无需GitHub账号。不要复制原作者桌面或文档目录的绝对路径；使用自己的长期安装目录。源码与手册可分享，但不得分享自己的Cookie、密钥、未脱敏上下文或机器配置。

## 自动准备新电脑

1. 检查Windows、浏览器和已安装版本；定位实际下载/源码目录。Chrome MV3与Native Messaging是当前实现基础。Edge可注册宿主，但不得把Chrome实测等同于Edge全部验收；macOS暂未实机验收。
2. 从上述项目的正式Release下载Chrome或Windows ZIP及SHA256SUMS，校验相应文件。先在临时目录解压并检查根目录manifest.json或整合包extension/manifest.json。来源/校验异常则停止替换，保留旧安装。
3. 解压到当前用户可写且长期保留的位置。仅注册当前用户，不申请管理员权限。Windows整合包含可审查宿主源码和EXE；当前安装器仍需要Node.js 22+及系统.NET Framework编译器。
4. 若需要CLI且Node缺失，维护AI可从Node.js官方渠道获取受支持的LTS版本，优先当前用户可用的安装方式；验证下载和版本后继续，不要求使用者手动研究路径。不能安装到受管理位置或出现必须用户接受的许可/权限提示时，再说明真实阻塞。
5. 在浏览器扩展管理页启用开发者模式，加载extension目录；仅Chrome插件ZIP则加载ZIP解压根目录。使用浏览器允许的自动化方式可自行完成；工具禁止访问管理页或必须本人确认时，由用户完成这一项。无需模拟真实鼠标。
6. 登录序图网站。正常账号登录由本人完成必要验证码；维护AI不能复制另一台电脑的Cookie或借用他人的身份。

## 安装本地CLI

安装器必须拿到这台电脑实际加载的扩展ID。可从浏览器扩展详情复制，或通过允许的只读扩展信息取得；不能沿用别人或上一台电脑的ID。拿到真实值后在整合包根目录运行：

```powershell
node --version
node native-host/install-windows.mjs ACTUAL_EXTENSION_ID
```

也可运行native-host/INSTALL-WINDOWS.cmd作为人工后备入口；维护AI已有扩展ID时直接使用上面的非交互命令，不再要求用户填写。安装器按本机Node与源码位置生成配置，注册当前用户Chrome/Edge宿主。必须保留解压目录；移动源码目录或Node路径后重新运行安装器即可重建路径。

插件中“更多→本地 CLI→测试本地 CLI”建立当前会话。连接后使用动态用户目录验证：

```powershell
$xutuCli = Join-Path $env:USERPROFILE '.xutu\windows\xutu.cmd'
& $xutuCli --help
& $xutuCli doctor
& $xutuCli tabs
& $xutuCli exec 'system version'
```

从tabs输出选择真实目标ID；若有多个网页且无法从任务唯一定位，先只读查看标题/上下文，不能盲选第一项。选择确定后：

```powershell
& $xutuCli compatibility --tab-id ACTUAL_TAB_ID
& $xutuCli context --tab-id ACTUAL_TAB_ID
```

ACTUAL_EXTENSION_ID/ACTUAL_TAB_ID是说明中的占位值，维护AI必须自动替换为已发现的实际值。插件不再提供复制 CLI 用法按钮；本机 CLI 通过 tabs 发现实际标签ID，换电脑/重开网页后必须重新发现。

## 更新与迁移

网站计划、审核与进度保存在服务器，登录后重新读取。当前版本没有跨电脑快照同步或自动迁移器；旧浏览器扩展本机快照不会因换电脑自动出现。需要旧快照时，先在旧设备根据已知backupId用system.backup.get读取，私下备份；不要声称存在尚未实现的一键快照导入。重要计划可用plan.export另存自己的私密备份，恢复前核对权限、版本和数据含义。

不要迁移以下机器文件：launcher.json、bridge-config.json、native-host.json及其中的密钥/管道名。新电脑由安装器重新生成。不要上传它们到公开仓库，也不要粘进兼容报告。

同一电脑升级时，优先保留扩展原加载目录；变更目录可能改变开发者扩展ID，必须重新核对并注册宿主。备份旧代码并确认没有在途写入，再替换为完整新版本。校验后重载扩展、重新连接CLI、读取版本与兼容状态。新的插件UI和功能行为会随完整包一起更新，不只更新CLI或文档。

浏览器管理页可自动操作时，在既有授权下由维护AI完成重载；无法通过工具操作时记录明确阻塞和所需一步，不反复询问“是否继续”。不为更新关闭所有浏览器或强行终止未知写入。升级验证失败则回退旧代码与本机注册，保留诊断信息；不重放业务指令。

## 分享给其他人

分享正式Release链接和本手册即可。插件不写死账号、计划编号、业务日期或原作者路径；各自登录各自账号，以服务器真实权限执行。提示词包含当前完整计划，复制前注意目标网页；兼容性报告不包含业务内容，优先用它向维护者反馈。

需要对方提供排查材料时，让其展开“更多 → 兼容性与排查”并复制状态。只有确实需要且得到对方授权时才索取完整上下文。GitHub推送、管理权限与升级软件本身的授权分开判断。

## 验收标准与边界

普通使用：可打开扩展、读取当前网站会话、复制提示词并粘贴单一JSON代码块。CLI使用：doctor、tabs、版本及compatibility往返成功。维护只做只读验收，不自动创建同事可见的测试计划。

当前已实测Windows既有安装；新电脑、所有Windows架构、Edge、离线依赖安装及迁移异常场景尚未全部实测。本手册规定可执行流程，不等同于已经实现无人值守升级服务或保证浏览器授权可完全省略。

## 一键复制给新设备 AI 的升级指令

展开插件“更多 → 软件更新”，点击“复制 AI 更新指令”。打开插件已自动查版本，复制时带该次结果与扩展 ID；换电脑必须重新定位实际路径与 ID，不照搬这些线索。复制文本没有网站计划或机器凭据。让有本机工具的 Agent 按文本完成可执行步骤，只有确实需要人工登录/浏览器许可等才报告；真实执行与验证结果由 Agent 如实给出。

新版插件使用“更多 → 本地 CLI → 测试本地 CLI”连接并分别验证宿主和选中网页。该测试不扫描其他网页；插件主界面多标签未选目标时必须明确选择。测试/诊断说明见 CLI_DIAGNOSTICS.md。

## 2.4 偏好与请求日志

长期偏好仅留在当前浏览器扩展本地存储，不自动跨电脑同步；同事首次使用默认中性表达。不要共享整个浏览器配置、作业日志或快照；它们可能含业务内容。新电脑重新登录后，可在更多→表达与修改偏好主动保存自己的选择。重装/清空存储会失去本机防重日志，不可把旧写入JSON当作安装测试重放。
