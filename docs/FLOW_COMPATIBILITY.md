# 外部流程图与序图：保留原图，分别核对结构与计算

适用 v3.0.2。首页流程不变：写需求 → 复制给 AI（同时提供原图）→ 必要澄清 → 粘贴 JSON。没有增加图纸上传器、解析器、本地问卷或偏好设置。

## 先明确允许改什么

确认图纸是名称、内容、编号和直接箭头的依据。合并品牌或客户方向，不等于允许调整其他分支。删除辅助点，不等于删除原来的分类节点；零耗时连线也不是一种节点。原成果表示完成，不可改成开始。

禁止新增节点时，AI 不得添加连接点，也不得换名称添加。允许建议估时，只授权估时，不授权拆分工作、改变前置或把并行串行化。用户排除的表达在本次对话中沿用，不保存为所有人的禁词。

AI 应在画图时就说明网站是否能等价表达，而不是画完再改业务。缺少原文、工期、人员或模型存在矛盾时一次汇总相关问题与限制，不规定固定题数、不重复询问已知内容。

## 四种结论分别看

| 检查 | 能说明什么 | 不能说明什么 |
| --- | --- | --- |
| 格式 | JSON、字段与有向无环图合法 | 图纸忠实、业务正确 |
| 图形一致 | 所附节点、名称/正文、直接箭头与候选图相符 | 工作开始时机正确 |
| 前置约束 | 所附工作开始受到所有所附前置成果约束 | 人员资源可并行、业务资料完整 |
| 工期映射 | 所附每项工作对应唯一实际工作边，三点估时一致，无未映射正工期边 | 原估时合理、截止可达、真实业务工作没有遗漏 |

网站保存及回读是另一个阶段，不是上述检查的同义词。插件无法核实外部 AI 是否忠实抄录图纸；所附资料通过检查不能冒称“业务已经认证”。

## 网站模型限制

网站用连线记录工期，工作从该连线起点事件完成时开始。A→C 为 3 天、B→C 为 0 天，只约束 C 完成，不保证 C 的 3 天工作等待 B。给两条入边都填 3 天则重复记录工作。总工期偶然相同不证明转换正确，调整工期后错误可能显现。

先核实单前置、已有真实前置链或现有等价汇合事件能否直接表达。复用已有事件必须保留其含义；不能增加串行依赖来省节点。同一人执行只影响资源安排，不自动增加业务依赖。

无法在用户约束内等价表达时，选项是：保留原图作为只读预览、用户明确接受后采用必要内部连接事件，或扩展网站模型。折叠显示只是隐藏内部节点，不是没有新增。本版没有实现折叠视图或网站新模型，也不会自动选择某一方案。

## 提交前自动对照：flowCheck

`plan.create` 和 `plan.batch` 新增可选 `params.flowCheck`。这是图纸清单校验，不是 draw.io 导入命令。现有其他业务命令不变。

- `nodes`：用户确认的完整目标清单，包含本次明确同意的修改。每项含 `id`、`name`、`kind`，可带 `content`。kind 为 `outcome`（完成成果）、`category`（原分类）、`event`（纯事件）、`auxiliary`（已明确同意的辅助点）。不会按名字猜类型。未提供 content 的节点正文不在原文比较范围。
- `dependencies`：确认后的全部直接箭头，使用 `from`、`to`。不仅比较可达性，也比较直接箭头；不自动删除已确认的传递性关系。
- `works`：完整确认工作表，每项含唯一 `id`、`fromNodeId`、`toNodeId` 和 `estimateDays`。工作须对应一条正工期边并通向完成成果。同一成果不能重复映射，所有正工期边及完成成果都须覆盖。分类、事件无实际工作时不填虚构估时。未知工期不能填零。

这是保守的一工作一成果映射；多工作联合产生同一成果等更复杂语义不能借此认证，应先核实，不拆分工期硬套。清单允许描述经过用户同意的辅助事件，但不自动插入、删除或折叠节点；必须将改动明确展示给用户。

执行顺序：读取最新计划与版本 → 本地形成最终候选图 → 对照确认清单 → 必要差异和映射错误集中报告 → 通过后一次受版本保护提交 → 服务器回读。批量内部中间态不会写入服务器。检查清单只用于插件校验，不进入网站保存请求。

报告包含新增/删除节点、名称/正文变化、箭头增删、祖先前置变化、估时变化和逐工作错误。修改已有计划时，同时返回网站当前内容到候选内容的实际修改摘要。未经授权的差异不能靠反向修改清单来消除。

带 flowCheck 的写入有差异或缺完整工作映射时拒绝提交。`mode: "preview"` 可以查看完整报告，即使无法提交；`mode: "validate"` 只验证格式。界面现在尊重这两个只读模式，省略 mode 默认为 execute。示例见 `examples/46-flow-preview.json`。

为了兼容旧指令，没有 flowCheck 的命令仍可执行。新建/批量结果会明确显示没有核实原图与工作映射，不声称检查通过。插件无法从任意自然语言或缺失原图中自动推导授权；不能以省略检查规避已知冲突。

## 出错时

图纸不符：复制执行结果给 AI，一次核对所有差异，只修改明确授权的字段。版本冲突：使用独立回读的最新状态，保留他人的日期、人员与进度；不猜版本。未知写入：检查原 requestId，不换 ID 盲目重试。普通文字修复继续用 node.batchUpdate；需要图纸对照时放入 plan.batch。

本地通过不等于生产写入通过。任何真实计划的修复均需要该计划的明确授权，本版维护回归没有修改真实业务计划。
