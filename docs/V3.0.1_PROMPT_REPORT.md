# v3.0.1 提示词与上下文调整报告

## 本次落实的五项修改

1. 基础兼容报告删除“问卷门禁已提供”的残留文字，改为页面摘要、HTML 导出及十批历史入口；继续明确并非导出/恢复写入认证。
2. 提示词与网站说明统一：普通修改通过校验后直接执行；删除、全量替换和恢复先显示实际差异，确认后执行。旧问卷错误码只解释为旧指令，不让用户寻找已删除的表单。
3. draw.io 规则仅在提示词中出现一次；信息摘要不再重复账号、完整日期/审核记录和权限。plan.batch 的子参数通过 JSON Schema 引用共享已列出的命令定义，保留完整约束与命令集合；实际执行契约继续展开，没有削弱校验。AI 被明确告知不能将 Schema 引用写进业务指令。
4. 复制提示词按本次需求选择项目组范围：管理计划默认只附当前关联组，新建未涉及分组时不附已有计划的分组清单；明确分组/项目组编号需求时附完整可见清单。没有关联组且不涉及分组时不请求清单。“不修改分组”“项目组保持不变”等不会触发完整清单。判断基于文本规则，不冒称完美语义理解；未附清单会明确注明，必要时 AI 可使用 project.list 核实。
5. task.merge 的正式 Schema 说明与提示词明确：至少三个依次相连的链节点，中间节点各一入一出；保留首尾、删除中间，已有基线/相关完成进度不直接合并。分支合并用 plan.batch，先核对外部依赖和估时，比较总估时与关键路径，不能擅自扣除混合工作的时间。

## 兼容性与不变范围

site.context 新增可选 params.projectGroups：all、selected、omit；省略仍保持原来的 all 行为。只影响上下文读取/复制，不改变计划分组或服务器权限。复制旧版完整上下文也会再次筛选项目组，且不修改原对象。

保留完整计划正文、稳定 ID、版本、人员、日期、审核、基线、完成进度、布局与原站分析。保留 JSON、plan.batch 单次提交、版本保护、防重复、历史恢复和脚本权限；无 CLI、Native Messaging、本地问卷/偏好、外观、AI Key 或 MCP 恢复。

## 验证结果

- 147 项 Node 单元/模拟接口/JSDOM/fake-indexeddb/本地 HTTP 测试通过；新增 7 项覆盖项目组范围、旧接口兼容、复制不修改数据、Schema 引用与原约束一致、提示词去重及兼容报告。
- 隔离 Chrome 157 合成页面、12 项恢复/错误界面检查及离线 HTML 回归通过。没有使用真实鼠标或修改生产计划。
- 用户提供的长提示词仅在本机内存中比较：约 4.8 万字符缩短到约 3.6 万字符，约减少 25%。未将其计划、人员或项目组内容写入仓库/公开附件。
