# 成果依赖与资源限制

业务依赖与资源约束严格分开：不能因为执行人相同就把全部工作机械串成直线。人员相同只说明实际排程需要错开，不是新的业务前置。节点正文中的“业务依赖”仅作说明，绝不能代替真实连线。成果前置表不是双代号网络边表：多前置先用必要的零耗时虚线汇合，再用一条实际工作边通向该成果；每项实际工作的原估时只计一次，不在各条前置边重复填写工期。保留成果编号，辅助节点另编并同步明确引用；不添加传递性冗余虚线。修改前读取最新原计划并核实每项实际工作与原边的对应，不猜测工期归属，不静默换算单位。输出前比较成果祖先集合与业务依赖闭包，检查无环、无冗余虚线和工作估时一一对应。单人资源排程另行说明，网站关键路径工期不能宣称为单人实际完成时间。

outcome-network.js为纯本地修复提案构建器，不自行写入网站。必须提供从最新计划核实的每项工作原边映射。已有未知辅助节点、遗漏工作或重复映射均拒绝，防止丢数据。不能从旧快照生成生产写入。

## 使用边界与验收（2026-11-11）

- 外部 AI 复制提示词和网站模型说明均已修正。没有新增界面问卷、CLI 或绕过参数契约的脚本入口。
- 构建器只输出提案，不是已注册的 JSON 业务命令，不能把其参数直接粘贴到插件执行。原始工作必须由最新数据核实，不能按节点数量猜工期归属。
- 原成果编号、名称、正文、负责人、日期、完成信息和既有坐标逐字保留；因此原成果引用无需改号。新增汇合节点使用未占用的 J 编号，并列出对应成果引用。未知旧辅助节点必须另行核实，不能自动删除。
- 生产执行须通过现有受权限和版本保护的操作；多步操作并非事务。每步用真实回读版本，失败时停止并核对已成功部分；禁止用 plan.replace 重置布局或基线。
- `node --test tests/*.test.js`：108 项通过，0 失败。其中新增 7 项为合成计划的单元测试，覆盖全部成果前置闭包、无环、无冗余虚线、工作估时一一对应、原字段保留、单人不强制串行、异常映射拒绝以及复制提示词。
- 这些是本地及既有模拟接口测试，不是生产写入测试。当前可访问的网站显示登录页，未取得目标最新计划，未执行真实修复，也未完成真实回读。不能据此报告真实计划已恢复。
- 本次代码修复尚未单独发布 Release；已安装扩展不会因源码修改自动加载新代码。

## 确认原文与用户明确取舍

确认过的成果表格是名称和正文的依据。AI 不擅自加“开始/完成”后缀，不把业务依赖、资源排班或工时换算说明塞进业务成果正文。缺失原文先索取，超过网站字段限制先说明，不静默截断。文字修复使用 `node.batchUpdate` 的 `name/content`，依据最新版本写入并逐字回读，其他字段保持。

旧任务转换器现在逐字保留任务名称及 `content`，缺省正文为空；旧协议 S/E 编号及显式 unit 换算兼容行为不变。工作起点明确标为辅助，不能当作新增业务成果。该旧格式转换不是保留原节点编号的修复工具，也不意味着允许对现有计划换算工期。

若使用者明确禁止辅助节点，应说明双代号表达限制；已经明确接受依赖缺失后，不重复问同一个选择，也不能把退化后的图说成完整业务网络。这是本次选择，不是所有用户的默认规则。保留实际工作及估时，不因删除汇合点顺便删除实际工作。网页删除节点可能全量重编号，需要保留原 ID 时应使用正式插件契约。

追加验证：111 项本地单元/模拟接口测试通过。新增覆盖确认表格逐字转换、辅助与业务成果可区分、name/content 批量写入前版本校验与写后回读，以及非文字字段保持。外部 AI 的自由生成不能由这些测试保证，实际输出仍须核对。

后续已恢复网站只读访问，真实读取目标版本及节点/连线；本轮尚未执行生产写入。插件安装刷新、生产删除与写后回读不属于本地测试通过范围。删除方案经过额外合成接口演练，不代表已经在网站删除。
