# v2.5.0 验收报告

基于 v2.4.0/e389aa6 与用户两份 v2.5 文档实施。最新要求优先：全面移除 CLI/Native Messaging；表达偏好移入问卷；使用帮助在主界面，不藏于“更多”。基线工作区干净，无无关用户修改被覆盖。

## 模拟新同事演示

输入：“老板叫我做一份 FPGA 核心板配套底板产品需求计划，至少20节点，尽量并行。”

首轮六题：①名称/编号（含三个候选）；②开工及是否硬截止；③实际项目组或不分组；④交付、优先级、业务限制、验收；⑤人员/设备、可并行范围、已知/待估工期；⑥面向谁、详细程度、名称/编号/改动范围偏好。

未答时，30节点 plan.create 在执行门禁返回 INTAKE_REQUIRED，POST=0。只答名称仍拒绝。完整回答后没有确认具体估时返回 ESTIMATE_NOT_CONFIRMED。确认后后台端到端用20节点、19条工作边的合成计划执行，当前账号成为计划owner，结果回读20节点；project.assignPlan 使用创建回读的真实模拟 targetId，组字段核对通过。改变提案估时、切换账号/标签/目标版本、组权限消失都再次拒绝。

“开工2026-11-12、不设必须完成日期、项目组PRJ-0097”直接预填，不重复问三项。仅改标题不追问人员日期。表达记忆、修改、重置按账号和新建/管理场景隔离。

## 恢复与可靠性

11批保留10；撤销3次至第8个标题、重做2次至第10个，新分支后旧redo不可用。同批三计划只一条；中间计划被同事更改截止后，其他目标可恢复、该目标冲突保留，返回 partial_undo，继续同方向不重复成功目标。新建撤销进入垃圾桶、重做使用原ID；分组被明确拒绝时记录创建成功部分。

快照保存后、写入之前日期被改动：写入使用快照真实版本而拒绝覆盖，独立诊断读到最新日期。多步修改使用回读版本2→3→4；不猜+1。创建已落库但响应丢失：结果未知，保留已知目标ID用于回读，不重复新建。审核自身操作及普通编辑引起的审核变化都不可谎报完整恢复。

## HTML 实测

原始1,300,902字节，静态离线1,301,383字节；跨域样式表和嵌套import两项缺失明确列出。Chrome新配置离线模拟下页面标题、图形、表格、弹窗、影子树与属性状态断言通过，禁用表单，测试恶意脚本未运行，网络写请求0。原始DOM不含shadow/property边界另有测试。丢块、过期、站点不匹配、字节/hash错误均拒绝不完整结果。

## 兼容与发布边界

原 JSON 业务、schema、请求ID、版本冲突独立回读、局部改名/重编号/引用/布局、幂等、未知结果、权限、虚线零耗时、图分析、原生计算桥、GitHub latest 检测及 JSON script.execute 回归。CLI/Native Messaging按最新要求删除，没有“仍兼容CLI”的承诺。

当前浏览器加载旧代码不会因文件修改自动升级。需要用户在扩展管理页重新加载；未操作真实鼠标。发布按现有 release.yml 生成草稿与附件，经已授权正式发布后验证，实际远端状态与提交号在最终交付报告列明；本文件不把本地打包当作已经发布。
