# AI提示词与问卷规则

提示词面向第一次接触序图的AI，不依赖它记得原对话。复制时读取完整计划、当前账号和目标版本、负责人/执行人、估时、日期、审核/基线、完成记录、任务表权限、原生评分计算及兼容报告；再附网站说明、操作契约与缺项摘要。重复的契约/规则单独列出，业务内容不截断。

## 先问还是直接给JSON

- 新建计划缺负责人、日期或工期：先询问本次需要确定的值，或是否明确允许默认/暂空/建议值。
- 已有计划只改标题：沿用人员和日期，不因无关空字段发问卷。
- 当前选中计划与新建需求无关：不得替换它；先判断新建目标及编号。
- 部门/角色只有“销售”“测试”：不编造具体账号，不默认所有人都是当前用户。
- 没有开工日：不能填今天；截止、预计完成、实际完成、审核时间互不替代。
- 上下文读取失败：提示缺失并先澄清，不能把“读取失败”理解为“新计划为空”。

问卷优先一次3–5个相关问题，给选项也允许自填；沿用已有回答，不将沉默当同意。用户可明确允许留空，不能无限阻止合理操作。

## 可复制输出

信息充分后，AI在聊天正文直接给一个完整json代码块。用户点击代码块复制，粘贴到插件JSON框执行。不能以文件附件、下载链接或sandbox链接代替；除非用户明确索要文件，不生成JSON文件。需要CLI时也先提供可复制JSON，仅在用户选择CLI执行后保存本机文件。

插件可识别带简短说明的单个JSON代码块；多个代码块、问卷和文件链接会提示重新复制，不猜测执行哪一段。剪贴板写入失败时会显示完整手动复制区，不假报成功。

## 业务与维护分开

业务计划含真实负责人、工期和日期，需要消除关键歧义。维护、升级、新设备安装不使用业务问卷；有工具和既有授权的维护AI按GITHUB_MAINTENANCE.md与CROSS_DEVICE.md自行执行到底，只有真实登录/授权或高风险越权边界才报告阻塞。

## 实际限制

这些是发给外部AI的明确指引，不能控制第三方模型实现。若它仍只给附件，可回复：“请直接在聊天正文提供一个完整可复制的JSON代码块，不生成文件；信息不足先问我。”插件会校验命令结构及真实网站权限，但不能替代用户对业务意图的判断。
