# v2.5 计划字段核实

|字段|核实与写入规则|
|---|---|
|名称|提供三项候选，也可自填；JSON 必须与已答名称一致，不添加“天制演示”等前缀|
|计划编号|用户核实后提交；服务器创建时检查唯一性。创建后不通过普通编辑修改编号|
|计划负责人|默认当前登录账号，只是计划层 owner，不自动填充所有阶段和工作的执行人。本地问卷创建流程暂只支持当前账号为计划负责人|
|开工|用户明确日期或明确暂不设置；缺省不是今天。字符串为有效 YYYY-MM-DD，草稿空值允许|
|硬截止|明确询问是否必须在某日完成；无硬截止为空。预计完成、实际完成、审核日期不得代替|
|项目组|读取实际 /api/project-groups 返回清单，选择有权访问的 ID 或明确不分组；不凭展示名称猜 ID|
|新项目组|问卷中的独立入口，填写编号与名称，使用现有 project.create 和当前账号；服务器拒绝则如实报告。成功后重新选组|
|节点负责人|node.ownerName / 更新时 set.owner，是阶段负责人或验收人；保留真实业务分工|
|工作执行人|边 executor；不把计划 owner 自动复制到全部工作。角色描述不等于真实账号|
|估时|minimum ≤ likely ≤ maximum，均非负；单位天。建议值先展示，再由用户确认，不能为了评分缩短真实工期|
|虚线|只能表示零耗时逻辑关系。等待、固化、审批等有历时过程仍是实际工作|
|计算|沿用网站原生 PERT、TE/TL、关键路径、评分和进度；不覆盖计算结果|

创建和分组不是事务：先 plan.create，写后读取真实 targetId；后续 project.assignPlan 用 planIdFrom:{stepId:"create",field:"targetId"}，并 dependsOn:["create"]。引用只允许前面已确认成功的创建步骤。创建成功但分组失败显示 partial_success；不自动删除新计划，不换 requestId 重建。

表达习惯、连续编号、节点数量属于用户选择；节点为事件/成果、边为工作/关系则是网站模型。过长、细碎、过多串行与虚线比例是质量建议，不阻止合法执行。实际资源不足时不伪造并行；合并保留必要工作、总估时、外部依赖和独立验收。

局部改名、编号映射和布局保护参见 [LOCAL_EDITING.md](LOCAL_EDITING.md)。日期、工期、人员、依赖、基线、审核和布局不因“整理表达”被全量替换。
