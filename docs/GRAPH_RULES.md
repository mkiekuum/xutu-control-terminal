# 编号、虚任务与依赖

计划编号是定位与区分记录的关键，创建后网站会锁定负责人/编号。插件不会为了提高评分或布局而改变已有编号。修改首选服务器ID；编号重名时拒绝猜测。

虚任务的三点估时均为0，常用于汇合、分流以及公共开始/结束点。但虚边也表达依赖，不只是装饰。例如0连接两个独立起始节点时，两个虚边都可能必要。节点名不能代替真实依赖判断。

如果已有A→B→C，再加A→C零耗时虚边通常冗余。graph.simplify逐条检查替代路径，只删除这类零耗时虚边，不改变节点和编号。若A→C是一项真实耗时工作，即使有替代路径也不会自动删除。

默认平均耗时超过14天时建议按可验收成果拆分；连续串行及同负责人节点需要核对是否确有成果依赖。不能为了评分随意并行，也不机械平分耗时。验收/评审/交付/里程碑/发布/完成节点不作为自动合并对象。本版仅给合并建议，不自动合并。
